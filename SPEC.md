# BookBridge implementation contract

Original contest-native app, not a ReadAI modification. Owner Alan Wen; MIT license for original code and synthetic examples. API access request accepted, key pending. Final contest goal requires LIVE Qloo integration, real MCP tool use, a polished publicly usable demo and public source; passing synthetic tests does not complete it.

Build a Python package providing FastAPI/static HTML/CSS/JS and official MCP SDK stdio tools. Two book-club members each choose 1–3 explicit movie/book/music artist anchors. Search first, user confirms Qloo entity IDs, then an agent tool finds shared books without inventing recommendations. Qloo is essential; no LLM-only recommendations or undocumented endpoint.

Verified primary contract:
- Hackathon base fixed https://hackathon.api.qloo.com; GET with X-Api-Key header, never query string or Bearer. Never accept user-specified upstream URL or forward secrets to redirects. Limit redirects/timeout/response size. No external model API, no arbitrary code/URLs.
- GET /search params query, types (urn:entity:book/movie/artist), take. Documented types and IDs differ from insights; allow only these supported categories.
- GET /v2/insights params filter.type=urn:entity:book, signal.interests.entities comma-separated UUIDs, take; Book supports filter.results.entities (comma-separated UUIDs) for rescoring specific candidates. Do NOT use /recs or /recommendations, filter.entities, generic custom filters, demographic guesses or health constraints. Unrecognized params can be silently ignored by Qloo.
- Search results and insights shapes must be tested against actual issued-key responses before claiming live success; expected search results list vs insights results.entities. Fail clearly on unknown shape, missing IDs/names/wrong type. Never silently create fallback live results.
- Initial 20 book candidates per member, union <=40, then rescore same union separately per member using filter.results.entities so ranks are comparable over the SAME candidate pool. Use rank-based maximin/shared ordering and an explicit stretch choice; missing results remain unknown, not zero affinity. Stable tie-breaking, duplicate IDs eliminated, exclude anchor book IDs, no repeated title choices. Show coverage and method, not a fabricated match percentage or causal explanation. Requested top-k max5.
- Bound search queries <=120 chars, only supported kind enums, UUIDs, 1–3 seeds/person, exactly2members. Do not trust or render upstream HTML/links/scripts. Extract only safe title/author/type/IDs/ranks. No raw response exposure. No user profile names needed.
- Private server-side cache TTL allowed, NEVER save Qloo responses in public repository/tests. Only invented books/anchors in a separate explicit sample/test path. Explicit sample mode label; no automatic fallback when live mode fails. UI status says live access pending if no key. Sample must use same ranking pipeline with a synthetic transport, no network. No side-effect actions, email, payment or identity inference.
- Production defaults use only QLOO_API_KEY if set, no dotenv autoload of parent project. No upstream call on import. API key never printed, returned, logged or sent to browser. Bounded cache/global quota and per-client rate limits, safe generic errors including401/429/5xx, no raw exception traces or input-taste access logs. Config names env example empty values.

MCP: PyPI currently mcp==2.3.0, official SDK2 uses from mcp.server import MCPServer, @mcp.tool(), stdio via CLI mcp run server.py or supported SDK run. Official README https://github.com/modelcontextprotocol/python-sdk and https://py.sdk.modelcontextprotocol.io . Do not assume FastMCP1.x. Expose search_taste_anchors and find_shared_read read-only tools over the same core; official MCP protocol tool discovery/call must be tested by parent, no print on stdio stdout. No native Chrome WebMCP claim.

UI: coherent responsive English product, clear two-member cards with search/disambiguation selection chips, live vs invented sample badge, shared and stretch recommendations, per-member coverage/rank explanation and tool trace. No fake testimonials, users, learning outcomes, brand logos or author covers copied from elsewhere. No paid/CDN scripts. Safe textContent rendering. Accessible form controls/keyboard/status, 390px no overflow. UI implementation details shown only when meaningful (mode/provenance/missing evidence).

Include install/start/MCP instructions and Dockerfile, pytest meaningful ranking/coverage/contract/endpoint validation/key-redaction/no-fallback tests.
